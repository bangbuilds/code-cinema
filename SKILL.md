# code-cinema

Turn an idea into a finished short film where everything — 3D objects, camera, typography, music — is code you can read, change and re-render. No stock footage, no models, no image or audio assets.

Two complete films were made this way and ship as examples:
- `examples/phone-eats` — 《一部手机，吞掉了多少东西？》(89.5 s): a phone "eats" 100 objects, 1973→2026; ends with a black screen in which the viewer sees their own reflection ("第 101 件").
- `examples/ai-eats` — 《AI 进食史》(82 s): the sequel; an AI text box eats the same 100 apps back out of the phone, 2022→2026.

## How it works (read this first)

1. **Everything is a pure function of time `t`.** `film.update(t)` sets every transform, uniform, text and screen pixel from `t` alone — no accumulated state, seeded randomness only. That is what makes scrubbing, frame-exact export and motion blur (averaging sub-frames) possible. Keep it that way in everything you add.
2. **One timeline drives picture and sound.** Every swallow, scan, typewriter cue and year roll is registered in `Timeline` as an event. `scripts/audio.mjs` synthesizes the soundtrack from the exported `events.json`, so sound lands on picture by construction.
3. **A repeated grammar.** Pick one action and repeat it (e.g. object emerges in color → scan line drains it to grey clay → an app icon peels off → flies into the phone's home-screen slot → the grey husk retreats). Viewers learn it in about three repetitions; after that you can speed it up, batch it, or reverse it, and the acceleration itself becomes the story.
4. **Steal structure, not subject.** Good references work because of devices — a cold open on the end state, one visual thread through every scene, beats that get closer together, minimal typography, callbacks, and a twist that only works on a phone. Keep the devices, change everything else.

## Workflow

Work in these phases. Each ends with something the user approves. Do not skip the 10-second sample: style mistakes are cheap there and expensive later.

### Phase 0 — Teardown (optional: only when the user gives a reference video)
A topic alone is enough to start (e.g. "帮我做一个《恐龙灭绝史》"); then go straight to Phase 1.
- Open it in the built-in browser. Grab frames by drawing the `<video>` element into canvases in a fixed overlay, three per screenshot (snippet in `references/workflow.md`). Sample every 2–3 s, densely in the first and last 5 s.
- Note: the hook (first 2 s), the connecting thread, pacing between beats, the typography system, palette and accent color, transitions, the ending twist.
- Summarize 4–6 structural devices to keep and say plainly that the subject will change.

### Phase 1 — Plan (get approval before building)
Give the plan in chat: one-line concept; the repeated grammar; chapters with timings (60–90 s total); the ending twist; 4–6 alternative directions in a table with a recommendation; reach mechanics; production approach; 2–3 decisions for the user. Verify every date, number and quote with web search, cite sources, and mark anything you could not verify. Use absolute dates in on-screen text ("2025 年 9 月 30 日"), never relative ones ("去年"). Patterns and pacing numbers: `references/storytelling.md`.

### Phase 2 — 10-second style sample
1. `cp -r <skill>/template <project> && cd <project> && npm install` (needs Node 20+, ffmpeg, Google Chrome).
2. Rewrite `src/film.js` (it ships a 12 s demo) into the hook plus one full grammar beat.
3. `npm run dev` for the live preview (Space plays, ←/→ steps a frame). Review with stills: `node scripts/export.mjs --url="http://localhost:5175/?export=1" --frames=0.9,2.5,4.0 --dir=out/stills`, tile them with `scripts/sheet.sh out/sheet.jpg 4 400 out/stills/*.jpg`, and actually look at the sheet. Fix and repeat.
4. Render the sample (`NAME=sample npm run render`) and send it. Ask about the look, the pacing and the text.

### Phase 3 — Full film
- Register everything in `Timeline`: `item()` for things that land on the phone (drives the counter and the home screen), `year()`, `layout()` (beat 4×6 → mid 5×8 → dense 7×15 as the grid fills), `text()` for bilingual subtitle cues, `event()` for anything the music should hit.
- Put special sequences in `src/seq/*.js` as classes with `update(t, camera)`; write camera keyframes per section with `makeCamPath`.
- Review section by section with stills. Check text collisions, overexposure, objects crossing the subtitle block, and props cut off by the frame. API reference: `references/engine.md`.

### Phase 4 — Render
- Always render from a frozen static build: `npm run render` builds, serves `dist/`, exports, synthesizes audio, muxes, and makes the cover. Rendering from the dev server breaks the moment any source file is saved, because the hot reload destroys the page.
- 60 fps with `SUB=8` motion-blur sub-frames; about 0.1 s per frame on an Apple M-series laptop (an 85 s film renders in about 9 minutes). Run it in the background.

### Phase 5 — Soundtrack
- `scripts/audio.mjs` composes with `scripts/synth.mjs` (FM music box, electric piano, pads, plucks, drums, risers, phone buzz, ticks, reverb). Map sections to layers so the music builds with the story, and map events to sound effects.
- You cannot listen, so measure: RMS per section (snippet in `references/audio.md`), dry/reverb balance, quiet sections within about 6–7 dB of loud ones. The render script normalizes to −14 LUFS, true peak −1.5 dB.
- Tell the user you verified by measurement only and ask them to listen.

### Phase 6 — Deliver and QA
- Pull frames from the final MP4 at key moments, tile them, look at them. Check duration, loudness, and black frames (`YMAX=0`) wherever pure black is intended.
- The render script also writes a `?cover=1` cover image and a "first-frame cover" version (2 cover frames at the head, cover art embedded), because many platforms use frame 0 as the thumbnail.
- Offer posting copy: title options, a hook line, and a making-of thread. Real numbers only (code lines, render time, the session's context tokens — say "context", not "billed").

## Things that will bite you

The ten most expensive lessons; the full list with fixes is in `references/gotchas.md`.
1. A `MeshStandardMaterial` without its own `envMap` uses `scene.environmentIntensity` and ignores `envMapIntensity`, so glossy screens turn grey. Assign `material.envMap = scene.environment` explicitly.
2. Motion-blur accumulation needs `renderer.autoClear = false`, or only the last sub-frame survives and the video comes out four times darker.
3. Never render from the Vite dev server (see Phase 4).
4. Bloom threshold ≥ 1.1 with strength around 0.42, so only emissive things glow; scan-line glow around 1.2.
5. Two-line bilingual subtitles push the text block down to about y = 510 px; keep objects, bubbles and props below about y = 540 px.
6. Things flying at the camera in vortex shots look enormous; spawn them in the mid-ground inside the frustum.
7. The browser pane throttles `requestAnimationFrame` when hidden; for inspection call `window.__film.frame(t)` directly.
8. Fonts: the entry preloads every CJK character found in the sources (`import.meta.glob('./**/*.js', { query: '?raw' })`). Strings that live in JSON will not be preloaded, so keep them in `.js`.
9. Pure-black endings need grain turned off (`film.grain(t)` returns 0) and an audio gate at zero.
10. No real brand logos and no original audio of real people. Generic glyphs and paraphrased quotes keep the film postable.

## Files

```
template/                 runnable starter (copy it per film)
  src/main.js             renderer, font preload, sub-frame renderAt, window.__film API, preview UI
  src/film.js             THE FILM: world, timeline, camera, update(t) — replace per project
  src/engine/             util (easing, rng), timeline, campath, hud (bilingual cues, odometer), post (bloom/grain/CA/accumulation)
  src/world/              phone (live home screen), beat (SwallowBeat grammar), materials (color-drain shader),
                          objects + objects2 (50+ procedural props), icons + icons2 (100+ app icons), textures, fx
  scripts/export.mjs      headless Chrome frame export → ffmpeg; --frames for stills, --events for events.json
  scripts/synth.mjs       code synthesizer + reverb + WAV writer
  scripts/audio.mjs       score for the demo (rewrite per film)
  scripts/render.sh       one-command pipeline (NAME, COVER_T, SUB, PORT env vars)
  scripts/sheet.sh        contact sheets for reviewing stills
examples/phone-eats/      full src + score of episode 1 (hook vortex, snake LCD, slot machine, street vortex, dessert, black-mirror ending)
examples/ai-eats/         full src + score of episode 2 (AI text box, chat bubble, glyph-token particles, resist/join beats)
references/workflow.md    frame-grab snippet, plan template, review checklist
references/engine.md      engine architecture and API
references/rendering.md   export, mux, cover, QA commands
references/audio.md       synth API, scoring, level measurement
references/gotchas.md     everything that went wrong and the fix
references/storytelling.md structure devices, pacing numbers, posting playbook for X
```

To run an example: copy `template/`, replace its `src/` and `scripts/audio.mjs` with the example's, then `npm install && npm run dev`.
